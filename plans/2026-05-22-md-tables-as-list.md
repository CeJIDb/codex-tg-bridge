# План: md-таблицы в список «ключ — значение»

**Дата**: 2026-05-22 **Задача**: конвертировать markdown-таблицы из ответов Codex в буллет-список и
попросить модель сразу выдавать списком, а не таблицей.

## Зачем именно так

Telegram HTML не поддерживает `<table>` — список допустимых тегов в
[core.telegram.org/bots/api#html-style](https://core.telegram.org/bots/api#html-style) (b, i, u, s,
code, pre, a, blockquote). Сейчас md-таблицы из ответов летят в чат сырым markdown'ом и читаются как
мусор. Альтернативы:

- ASCII-сетка в `<pre>` — проигрывает по UX (горизонтальный скролл на мобильном, padding ломает
  копипаст) и по токенам (padding-пробелы по ширине самой длинной ячейки).
- Картинка/Telegraph — внешняя зависимость, против минимализма из CLAUDE.md.
- **Список `• <b>ключ</b> — значение`** — читается на любой ширине, минимум разделителей, выигрывает
  и по UX, и по токенам.

## Цель

Markdown-таблица в ответе Codex приходит в Telegram как буллет-список с жирной первой колонкой.
Модель сама предпочитает список таблицам — таблица остаётся как fallback на случай, если модель
всё-таки её выдала.

## Scope

Входит:

- Парсер md-таблиц в [src/format.mjs](../src/format.mjs).
- Правки [src/prompt.mjs](../src/prompt.mjs): запрет md-таблиц, требование списка.
- Тесты в [test/format.test.mjs](../test/format.test.mjs).

Не входит:

- ASCII-рендер в `<pre>`.
- Поддержка экранированных `\|` внутри ячеек.
- Поддержка многострочных ячеек.

## Определение «готово»

- [ ] Двухколоночная md-таблица → `• <b>val0</b> — val1` на строку.
- [ ] Таблица с ≥3 колонками → блок: первая строка `• <b>val0</b>`, дальше `<отступ>header_i: val_i`
      с отступом в 2 пробела.
- [ ] Таблицы внутри блоков кода (`…`) не трогаются.
- [ ] `prompt.mjs` содержит явное правило: «не используй md-таблицы, выдавай список».
- [ ] `npm run test:format` зелёный, новые кейсы покрывают 2-кол, 3-кол, таблицу в code-блоке.
- [ ] `npm run ci:check` зелёный.

## Итог

Готово. Сделано:

- `src/format.mjs`: новый шаг 2.5 в `mdToTgHtml` — `mdTablesToList()` парсит md-таблицы построчно и
  заменяет их на буллет-список в markdown-разметке (`*` + `**…**`), которую далее обрабатывают
  существующие шаги конвертера. Парсер пропускает таблицы внутри плейсхолдеров блоков кода
  `FMTCB\d+`, потому что эти строки уже не содержат `|`.
- `src/prompt.mjs`: добавлен раздел «Формат таблиц» — модели запрещены md-таблицы и `|---|---|`,
  требуется буллет-список вида `- **термин** — значение`.
- `test/format.test.mjs`: 4 новых кейса (2-кол, ≥3-кол, code-block-не-трогаем, текст вокруг
  таблицы), все зелёные. `npm run ci:check` зелёный.
