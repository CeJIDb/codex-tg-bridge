# Подготовка graphify-репозитория

Бот не хранит знания: он опрашивает Codex по внешнему репозиторию-графу из `GRAPH_REPO_PATH`. Граф —
это git-репозиторий с Markdown-документами и точкой входа `MANIFEST.md`. Подойдёт любой домен,
который атомизируется в Markdown: нормативка, регламенты, методички, требования к продукту.
Собирается скиллом [`/graphify`](https://github.com/safishamsi/graphify).

## Минимальный скелет

```text
my-domain-graph/
├── MANIFEST.md         ← обязателен: оглавление + правила цитирования
└── sources/            ← .md-атомизации исходных документов
    └── *.md
```

`MANIFEST.md` — единственный обязательный файл. Лоцман читает его первым и навигируется по ссылкам
внутри (см. [src/prompt.mjs](../src/prompt.mjs) — системный промпт описывает протокол).

## Расширенный скелет

Для серьёзного домена удобнее структура со словарём сущностей и кросс-вокками:

```text
my-domain-graph/
├── MANIFEST.md         ← точка входа для агента
├── README.md           ← обзор для людей
├── ONTOLOGY.md         ← закрытый словарь сущностей и инвариантов
├── GOLDEN_SET.md       ← фиксированный набор запросов для проверки графа
├── sources/
│   ├── INVENTORY.md    ← реестр всех .md с метаданными
│   ├── PAYWALL.md      ← платные/закрытые источники (опц.)
│   └── <prefix>/       ← группировка по издателю: rmrs/, iec/, internal/...
├── crosswalks/         ← сопоставления между источниками (ISO ↔ ГОСТ и т.п.)
├── topics/             ← тематические срезы — готовые «взгляды» на граф
└── .graphifyignore     ← что не индексировать (артефакты, секреты, черновики)
```

Ключевые файлы:

- **`MANIFEST.md`** — служебный документ для агента: что это за граф, какие верхнеуровневые
  директории есть, формат цитирования (например, `sources/<publisher>/<doc>.md#<anchor>`).
- **`ONTOLOGY.md`** — закрытый словарь типов сущностей домена. Чем уже, тем меньше галлюцинаций.
- **`sources/*.md`** — один файл на один логический фрагмент (глава, требование, раздел) со
  стабильными anchor'ами. PDF-исходники не коммитим — храним отдельно или ссылками.

## Шаги

1. `git init my-domain-graph && cd my-domain-graph` — никакого фреймворка, просто Markdown + git.
2. Атомизируйте источники в `sources/`. Имена файлов — латиница, kebab-case.
3. Опишите `ONTOLOGY.md` — типы сущностей и инварианты. Без словаря качество ответов резко падает.
4. Соберите `MANIFEST.md` как точку входа.
5. (Опц.) Добавьте `topics/`, `crosswalks/`, `GOLDEN_SET.md` — когда нормативка разнородна и нужна
   регрессия на «золотых» вопросах.
6. Запустите [`/graphify`](https://github.com/safishamsi/graphify) в корне репо — он соберёт
   `graphify-out/GRAPH_REPORT.md` и индекс.
7. Пропишите `GRAPH_REPO_PATH=/абсолютный/путь/к/my-domain-graph` в `.env` бота и перезапустите его.

## Антипаттерны

- **Бинарники в графе.** PDF, docx, картинки — отдельно или ссылками. Граф остаётся текстовым.
- **Смешанные домены в одном репо.** Один граф — один скоуп. Дешевле завести второй.
- **Запись из бота.** Флаг `--sandbox read-only` в [src/codex.mjs](../src/codex.mjs) — контракт
  безопасности. Если нужна запись из чата — это другой проект.
- **Граф без `MANIFEST.md`.** Агент не знает, с чего начать навигацию.
